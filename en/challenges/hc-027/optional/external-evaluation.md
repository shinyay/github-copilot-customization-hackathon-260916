# Consider an external evaluation tool / service

**Language:** [日本語](../../../../challenges/hc-027/optional/external-evaluation.md) / **English**

[Return to the main scenario](../README.md)

## Purpose

Organize the verification procedure for using an external evaluation tool or service separately from the exercise with 18 synthetic rows. Do not infer commands, supported models, pricing, or transmission scope from a name. Try only the smallest configuration that can be confirmed from primary sources.

## Prerequisites

- You can confirm the publisher, official distribution source, supported version, and terms of use
- You can confirm the authentication method, target model, and eligibility to use the service
- You can explain which prompt, response, source, and metadata will be transmitted
- You can prepare an isolated validation environment and a cost ceiling

## Permissions and safety

- Obtain separate approval for download, installation, login, model use, external transmission, and billing.
- Do not send private prompts, source, tokens, or personal information without approval.
- Do not try commands or unofficial binaries that cannot be confirmed through official sources.
- Do not replace measurements of real model performance or educational effects with the synthetic results.

## Procedure

1. Record the publisher, version, official URL for the binary / service, and whether a checksum is provided.
2. Confirm the data flow, retention period, use for training, region, and deletion method.
3. As in the main scenario, freeze the rubric, denominator, order, stop conditions, missing-data handling, and cost ceiling before viewing results.
4. Prepare the smallest synthetic sample that contains no private data.
5. Run it once using an approved method, and record the tool version, model, input scope, error, duration, and cost.
6. Stop further execution if there is unexpected transmission, a permission request, cost, or result format.
7. Store the external evaluation record separately from the 18 synthetic rows in the main scenario.

## What to observe

- publisher / tool or service / version
- authentication / permissions
- model / region / data sent / retention
- rubric / sample identity / execution result
- duration / cost / error
- cleanup / deletion confirmation

## Stop conditions

- The publisher, version, or official acquisition source cannot be confirmed
- Installation, login, external transmission, model use, or billing has not been approved
- Private data cannot be excluded from transmission
- Data retention, region, or deletion method cannot be confirmed
- Supported commands or pricing conditions cannot be confirmed from primary sources

Record the stop reason and return to the local synthetic evaluation in the [main scenario](../README.md).
