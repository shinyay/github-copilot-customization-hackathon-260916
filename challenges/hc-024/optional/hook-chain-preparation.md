# Stop 通知経路を比べる

**言語:** **日本語** / [English](../../../en/challenges/hc-024/optional/hook-chain-preparation.md)

## 目的

[HC-024のメインシナリオ](../README.md)で使う「1つの要因だけを変える」という考え方を、同じ限定的なチェッカーの呼び出し経路に応用します。チェッカーを接続しない場合、手動実行する場合、Stop通知へ接続する場合の3経路を観察します。

Stop通知は、非ブロッキングの通知として扱います。品質ゲート、ツールの拒否、自動修正、会話の終了保証とはみなしません。

## 前提

- 対応するLocal / Preview環境とStopイベントを利用できる。
- 許可済みの使い捨て検証用ワークスペースがある。
- 同じ入力だけを検査する、小さな読み取り専用チェッカーを用意できる。
- チェッカーの実行、Hookの設定、イベントの試行、通知の観察、終了後の解除を個別に承認できる。

## 権限と安全

- このガイド自体は、Hookやスクリプトの実行権限を付与しません。
- チェッカーは固定入力の形式だけを確認し、ソースや回答を変更しません。
- 通知後も処理が続くことを前提とし、拒否、権限変更、再試行ループ、自動修正へ拡張しません。
- 3つの経路で同じチェッカーと同じ入力を使います。
- この教材リポジトリには、有効なHookやチェッカーを追加しません。

## 手順

1. チェッカーの入力、確認項目、出力、最大実行時間を固定します。
2. 未接続の状態で、チェッカーが自動実行されていないことを確認します。
3. 同じ入力でチェッカーを手動実行し、形式の確認結果を記録します。
4. 許可済みの別のワークスペースでのみ、同じチェッカーをStop通知へ接続します。
5. Stopイベント、チェッカーの起動、通知の表示、再入防止を別々に観察します。
6. 検証後に設定を解除し、残っているプロセスや変更がないことを確認します。

## 観察すること

- イベントが発生したか。
- チェッカーが同じ入力で起動したか。
- 形式結果と通知内容が一致したか。
- 通知が、回答の意味評価やツールの拒否に変わっていないか。
- チェッカー自身が再びStopイベントを発生させる場合に、再入を避けられたか。
- 後片付け後にHookやプロセスが残っていないか。

手動実行が成功しただけで、Hookの検出、イベント、通知UIの成功を主張しません。通知の成功も、回答品質や教育効果を証明するものではありません。

## 停止条件

- イベント、作業ディレクトリ、再入判定に必要な情報が得られない。
- 未観測値を既定値で補う必要がある。
- スクリプト / Hookの配置やイベントの試行が承認されていない。
- 非ブロッキング通知を、拒否や品質ゲートに変える必要がある。
- チェッカーが書き込み、外部送信、長時間の実行を要求する。
