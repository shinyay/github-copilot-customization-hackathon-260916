# 四機構を一つずつ外す

**言語:** **日本語** / [English](../../../en/challenges/hc-024/optional/ablation-preparation.md)

## 目的

[HC-024のメインシナリオ](../README.md)は、InstructionsとSkillの2要因を扱います。この補足ガイドでは、Instructions / Skill / Custom Agent / MCPの `full` 構成から1つずつ外し、どの構成要素が観察結果に関係したかを整理します。

調べるのは `full` と4つの一要素除去を合わせた5行です。全16通りの組み合わせを網羅する設計ではありません。

## 前提

- メインシナリオの固定ソース、合成運用メモ、リクエスト、評価観点を理解している。
- Custom Agent と MCP を利用できる、許可済みの使い捨て検証環境がある。
- 同じモデル、実効ツール、ソース、メモの全文、リクエストを各行でそろえられる。
- Agentの選択、ローカルサーバーの起動、server trust、リソースの添付を個別に承認できる。

## 権限と安全

- このガイド自体は権限を付与しません。
- MCPは承認済みの読み取り専用リソースだけを対象にします。
- Agentのツール宣言を、実効ツールやOS権限と同一視しません。
- 書き込み、ターミナル操作、外部送信、通常のプロファイルの変更は追加しません。
- MCPを外す行でも、同じ運用メモの全文を通常のファイルとして渡し、情報量をそろえます。
- この教材リポジトリには、有効なAgent / MCP設定を作りません。

## 手順

1. `full` 構成のI、Skill、Agentの役割、MCPリソースを固定します。
2. 次の5行を作ります: full、without-instructions、without-skill、without-agent、without-mcp。
3. 各行で同じソース、メモ、リクエスト、モデル、実効ツール、評価観点を使います。
4. without-mcpでは、MCPが返す予定だったメモと同じ全文をファイルとして提供します。
5. presence、discovery、loading、リソース取得、usage、出力への影響を別々に記録します。
6. 一度に複数要素が変わった行は比較対象から分けます。

## 観察すること

- Agentが選択されたことと、その指示やツールが実際に使われたこと。
- リソースを添付したことと、モデルがツールを選んで呼び出したこと。
- MCP経由とファイル経由で情報量が同じか。
- `full` から1要素を外したときの差を、事前に決めた評価観点で説明できるか。
- 未観測や未利用を `false` や成功に置き換えていないか。

5行だけから、未実施の組合せ全体や一般的な因果関係を主張しません。

## 停止条件

- 未承認のサーバー、trust、Agentの選択、リソースの添付が必要になった。
- without-mcp だけ情報量が変わった。
- モデルや実効ツールをそろえられない。
- リソースの取得やツールの呼び出しを観察できない。
- 書き込み、外部送信、追加権限が必要になった。
