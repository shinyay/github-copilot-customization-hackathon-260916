# `CLAUDE.local.md` と `.claude/rules/` を別々に検討する

**言語:** **日本語** / [English](../../../en/challenges/hc-004/optional/claude-variants.md)

[HC-004 本編へ戻る](../README.md)

## 目的

ルートの `CLAUDE.md` を扱う本編とは別に、ローカル専用の指示と、パスを限定した Rules を検討するための
補足ガイドです。二つは目的も観察点も異なるため、同時に有効化して一つの比較にはしません。

参考: [VS Code Custom instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions)

## 前提

- 利用予定のクライアントが対象形式に対応していることを、現在の公式資料で確認できる
- ルートでの試行とは別に、使い捨てのワークスペースと新しい会話を用意できる
- 既存のリポジトリ、home、User、organization の Instructions の有無を確認できる
- 本編で使ったモデル、ハーネス、ツールを変えずに試せる

## 権限・安全

- ワークスペースまたは端末の所有者から、今回追加する非機密の指示だけを試す承認を得ます。
- 既存の home の Instructions、User 設定、organization 設定は削除も退避もしません。
- シークレット、個人情報、実データ、業務上の答えは書きません。
- この教材リポジトリには、有効な `CLAUDE.local.md` や `.claude/rules/` を追加しません。
- ルート、ローカル、Rules は一度に一つだけ試し、どの保存元が影響したか分からなくなる状況を避けます。

## 手順

### A. `CLAUDE.local.md` を検討する

1. ローカル環境だけで使いたい短い規則と、その理由を決めます。
2. **`local` という名前だけでは Git からの除外を保証しない**ことを前提に、使い捨てのチェックアウトで
   追跡状態と除外規則を別々に確認します。

   ```powershell
   git ls-files --error-unmatch -- CLAUDE.local.md
   git check-ignore -v -- CLAUDE.local.md
   ```

3. 一方で追跡対象として表示されたか、もう一方で一致した ignore 規則が表示されたかを分けて読みます。
   出力がないことだけを「除外済み」の根拠にはしません。
4. 承認済みの独立した試行でのみ新しいファイルを作り、固定依頼を新しい会話で一度試します。
5. 終了後は、自分が追加したファイルだけを取り除きます。

Git から除外されていても、シークレットを保存してよいわけではありません。また、Git の状態だけでは、
クライアントによる検出や本文投入は分かりません。

### B. `.claude/rules/` を検討する

1. 対象にしたいパスと、対象外として観察したいパスを先に決めます。
2. Rules でパスを選択するには、`applyTo` ではなく **`paths` 配列**を使います。次は構文確認用の、
   無効な状態の例です。

   ```yaml
   ---
   paths: ["wholesale-core/src/**/*.java"]
   ---
   ```

3. 本文には一般化できる短い規則だけを書き、受注承認の答えは含めません。
4. 承認済みの独立した試行で、一致する Java ファイルと一致しないファイルを別々に開きます。
5. クライアントが示す参照元、送った依頼、回答を保存します。対象外でも作用したように見える場合は、作業を止めます。

## 観察すること

- 保存したパスと本文
- クライアントがどのソースを検出したと表示したか
- 本文が渡ったと直接確認できる情報があるか
- ローカルファイルの追跡状態と除外規則
- Rules の `paths` に一致するファイルと、一致しないファイルでの違い
- ルートや既存の home / User / organization の Instructions が混ざった可能性
- 回答に表れた意図と、確認できない内部処理

同じ本文でも、メタデータ、優先順位、検出範囲まで同一になるとは限りません。

## 中止条件

- クライアントの対応状況、環境所有者の承認、分離方法のいずれかを確認できない
- 既存ファイルの上書き、ignore 規則の変更、force-add が必要になる
- ルート、ローカル、Rules、複数の外部 Instructions を一つずつ切り分けられない
- home の変更や既存設定の削除が必要になる
- 対象外のパスにも作用した可能性があり、原因を説明できない

中止しても HC-004 本編は完了できます。対応していない形式では、本文を手動で渡して内容だけを確認できますが、
その形式での検出を試したことにはなりません。
