# Cloud Agent でテスト案を試す

**言語:** **日本語** / [English](../../../en/challenges/hc-029/optional/cloud-test-proposal.md)

[← HC-029 のメインシナリオ](../README.md)

## 目的

HC-029 で作成した不活性なルールとテスト案を、承認済みの専用リポジトリで Cloud Agent に渡す前の確認事項を整理します。提案した差分を既存の作業へ自動適用する手順ではありません。

## 前提

- Cloud Agent と対象リポジトリを利用できる
- 開始ブランチと変更先ブランチを明確にできる
- JDK 8、Maven 3.9 系、Java 7 互換条件を確認できる
- 対象テストのパスと、変更禁止パスを確認できる

## 権限と安全

- Cloud Agent のタスク、モデルの利用、ブランチの作成、変更提案、テストの実行、費用について事前承認を得ます。
- 代替手段としてプロダクションコード、`pom.xml`、既存テストの期待値を変更することはありません。
- active Instructions を配置する場合は、対象リポジトリの所有者が内容と解除手順を確認します。

## 手順

1. 固定依頼、ルールの本文、ソースのリビジョン、対象テストのパスを記録します。
2. ルールを使わない試行と使う試行を分ける場合は、同じソースと依頼を使います。
3. Cloud Agent には提案範囲を `CommonRulesTest.java` だけと明示します。
4. 生成された変更は自動でマージせず、プロダクションコード、POM、既存の期待値に変更がないかレビューします。
5. JDK と Maven のバージョンを確認してからコンパイル/テストを実行し、コマンドと終了結果を記録します。
6. 試行後は自分が追加した active customization だけを解除します。

## 観測すること

- ルールがタスク固有の依頼を必要以上に重複していないか
- 提案が対象のテストファイルだけに収まっているか
- JDK/Maven の実際のバージョンと互換性要件
- 実行したコンパイル/テストと未実施の確認
- ブランチ、モデル、ツール、入力の差による比較不能の要因

## 停止条件

- Cloud Agent、リポジトリ、ブランチ、JDK、Maven のいずれかを確認できない
- タスク、モデル、費用、変更、テストの承認がない
- プロダクションコード、POM、既存の期待値を変更する必要がある
- ソースや入力を公平にそろえられない
- 実行していないテストを成功として扱う必要がある
