# 使い捨てワークスペースでStop Hookを観察する

**言語:** **日本語** / [English](../../../en/challenges/hc-010/optional/stop-preview.md)

このガイドは[HC-010本編](../README.md)の補足です。本編はHookを有効にしなくても完了できます。

## 目的

合成草稿に対するチェッカーの結果、Stopアダプターの出力、実際のStopの発火、画面通知をそれぞれ観察します。通知が返されたことを、形式検査への合格や内容の正しさと同一視しないことが目的です。

## 前提

- 利用中のVS CodeとCopilotがAgent HooksおよびStop Hookに対応している
- extension hostのOSとNode.js 22以降を確認できる
- 既存のHookから分離できる使い捨てワークスペースを用意できる
- 組織ポリシーとワークスペースの所有者がHookの追加を許可している

## 権限と安全

- `starter\` のファイルは不活性な原稿です。このリポジトリ内では `.template` を外しません。
- 別の使い捨てワークスペースへ、今回使うヘルパー、合成草稿、設定だけをコピーします。
- `continue: true` を維持し、`decision: "block"`、自動修正、追加ターン、再試行ループを追加しません。
- 既存のUser/Home Hookを削除したり上書きしたりしません。終了時に削除するのは、今回自分で追加したものだけです。

## 手順

1. 本編の `manual\hc-010` の構成に従い、三つのヘルパーと合成草稿を使い捨てワークスペースへコピーする。
2. Hookを使わずにチェッカーを手動で実行し、草稿の見出し構造と結果を確認する。
3. 合成Stop入力をアダプターへ渡し、`continue: true`、`systemMessage`、チェッカーの結果の関係を確認する。
4. `starter\customization\stop-hook.json.template` を参照し、対象製品の公式手順に従って、使い捨てワークスペースだけにStop Hookを設定する。
5. 合成草稿を対象にAgentを一度だけ実行し、現在のAgent実行が停止するときにHookが呼ばれたか確認する。
6. チェッカーの結果、アダプターの出力、製品が表示した通知をそれぞれ記録する。画面通知が見えなくても、推測で補わない。
7. 今回追加したHook設定と作業ファイルだけを削除し、元の選択状態に戻っていることを確認する。

## 観察すること

- 手動で実行したチェッカーとHook経由のチェッカーが、同じ草稿を読んでいるか
- `pass`、`invalid`、`uncheckable`、再入時の `skipped` が混同されていないか
- アダプターの通知文に、形式検査だけを行ったことが明記されているか
- Stopが会話やウィンドウの終了ではなく、現在のAgent実行の停止に対応しているか
- 他のHookやUser設定が結果に混入していないか

## 停止条件

- Hooksが利用できない、または組織ポリシー・所有者承認を確認できない
- extension hostのOS、Node.js、設定場所を確認できない
- 既存のHookと今回の追加分を分離できない
- ブロッキング処理、外部接続、権限変更、既存設定の削除が必要になる
- 今回追加した設定だけを安全に解除できない

停止した場合は、本編の手動確認と通知設計へ戻ります。
