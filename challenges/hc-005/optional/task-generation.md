# 用途別生成の入口を小さく試す

**言語:** **日本語** / [English](../../../en/challenges/hc-005/optional/task-generation.md)

[HC-005 本編へ戻る](../README.md)

## 目的

選択範囲のレビュー、コミットメッセージ、Pull Request の説明のうち一つについて、
用途別の指示を保存し、生成機能の入口で利用される様子を小さく観察するための補足ガイドです。
通常の Chat と用途別生成は別の入口なので、同じものとして扱いません。

参考: [VS Code Custom instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions)

| 用途 | 設定 key | 固定する入力 |
| --- | --- | --- |
| 選択範囲のレビュー | `github.copilot.chat.reviewSelection.instructions` | 同じファイルの同じ選択範囲 |
| コミットメッセージの生成 | `github.copilot.chat.commitMessageGeneration.instructions` | 同じステージ済みの差分 |
| Pull Request の説明生成 | `github.copilot.chat.pullRequestDescriptionGeneration.instructions` | 同じ差分と Pull Request の前提 |

値は `text` または `file` を持つオブジェクトの配列です。本編では、`text` を使った無効な草稿だけを扱います。

## 前提

- 対象の VS Code と拡張機能のバージョン、選んだ生成機能の入口を特定できる
- その入口を利用できる契約・権限を確認できる
- 合成入力だけを含む、使い捨て可能なワークスペースを用意できる
- 既存設定と今回の追加分を区別し、元へ戻せる

## 権限・安全

- ワークスペースの所有者から、選んだ設定一つと合成入力だけを扱う承認を得ます。
- 三つの key を同時に有効化しません。
- 既存設定を全文置換せず、元値と今回の追加分を記録します。
- コミット、プッシュ、Pull Request の作成、投稿は、生成とは別の副作用です。このガイドでは実行しません。
- この教材リポジトリの
  [`generation-settings.json.template`](../starter/generation-settings.json.template) は無効な状態のまま保ちます。
- `.vscode/settings.json` がリポジトリの方針で無視される場合、ignore の変更や force-add は行いません。

## 手順

1. 三つの用途から一つだけ選ぶか、「追加なし」を選びます。
2. [`generation-settings.json.template`](../starter/generation-settings.json.template) の作業用コピーへ、選んだ key と
   `{"text": "自分で設計した本文"}` だけを残します。
3. 指示なしと指示ありの両方で使う、共通の合成入力を決めます。
   - レビュー: 同じファイルと同じ選択範囲
   - コミットメッセージ: 同じステージ済みの差分。作業用リポジトリ以外のステージは変更しない
   - Pull Request の説明: 公開や投稿を伴わないテスト用の同じ差分と前提
4. 承認済みの使い捨て環境で、既存値を上書きしない方法が確認できた場合だけ設定を追加します。
5. 新しいコンテキストで、指示なしと指示ありを一度ずつ呼び出し、使った生成ボタンやコマンドをそのまま記録します。
6. 出力を保存した後、今回の設定だけを取り除き、ステージや外部項目を変更していないことを確認します。

通常 Chat に同じ本文を貼る試行は参考にはなりますが、同じ用途別入口へ同じ追加本文が渡ったと
確認できない限り、等価な比較とは呼びません。

## 観察すること

- 選んだ key、保存場所、追加した `text`
- 固定した選択範囲または差分
- 実際に使った生成入口
- クライアント / 拡張機能 / バージョンと、利用された設定ソースの表示
- 出力の構造、事実誤認、不要な長文化
- 保存、検出、本文投入、入口の呼び出し、出力、外部投稿の有無
- utility model など、通常の Chat と同じだと確認できない要因

構文が正しいことや見出しがそろったことだけでは、内容の正確性や指示の効果を証明できません。

## 中止条件

- 対象の入口、権限、固定入力、元に戻す方法のいずれかが不明
- 既存設定の上書きや、ignore 規則の変更、force-add が必要
- 既存のステージ、Pull Request、リモート項目を変更する必要がある
- コミット、プッシュ、投稿、拡張機能の追加が必要
- 指示なしと指示ありで同じ入力を用意できない

中止した場合は、無効な状態の構文草稿、または「追加なし」とした理由まで記録すれば十分です。
