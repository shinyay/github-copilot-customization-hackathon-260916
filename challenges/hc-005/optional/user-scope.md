# User 指示の保存先と分離を確認する

**言語:** **日本語** / [English](../../../en/challenges/hc-005/optional/user-scope.md)

[HC-005 本編へ戻る](../README.md)

## 目的

個人向けに設計した短い指示を User の範囲で試す前に、保存先、対象ホスト、既存設定との分離、
解除方法を確認するための補足ガイドです。本編の草稿を作っただけでは、User 指示として保存、検出、再利用された
ことにはなりません。

参考: [VS Code Custom instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions)

## 前提

- 利用する VS Code と Agent Host のバージョンと種類を特定できる
- 使い捨て可能なプロファイル、テスト用ワークスペース、新しい会話を用意できる
- User 指示を試せる契約・製品設定を本人が確認できる
- 今回の追加分を既存の個人設定から識別できる

現在の資料では、User 向けの保存先として `~\.copilot\instructions` や `~\.claude\rules` が説明されています。
対象ホストが読む場所は、現在の公式資料で確認してください。新しいリポジトリや VS Code のプロファイルを作っただけで、
HOME 配下の保存先まで分離されたとは限りません。

## 権限・安全

- 端末とアカウントの所有者から、今回追加する一つの非機密の指示について、保存、確認、解除の承認を得ます。
- 既存の User instructions、Settings Sync、ほかのプロファイル、organization instructions は削除も退避もしません。
- シークレット、個人情報、顧客データ、実在する業務上の判断は書きません。
- この教材リポジトリには、有効な User instruction を作りません。
- 元の状態や解除方法が分からない場合は、実機試行を始めません。

## 手順

1. 対象ホストと、現在の公式資料が示す保存先を確認します。
2. 既存内容を転載せず、今回の追加分を識別できるファイル名、短い本文、所有者、削除予定時点を決めます。
3. 本編の合成カードから、業務上の答えを含まない個人の表示上の好みを一つ選びます。
4. 承認済みの使い捨て環境でのみ、その一文を対象の User 保存先に追加します。既存のファイルは上書きしません。
5. 新しい会話で、同じ合成タスクを二つのワークスペースから一度ずつ試します。
6. クライアントが参照元を表示する場合は、その表示を、送信した依頼や最初の出力とは分けて記録します。
7. 試行後は今回追加したファイルだけを削除し、既存設定が残っていることを確認します。

## 観察すること

- 保存先、ファイル名、本文、追加・削除した時点
- クライアント / ホスト / バージョンと、どのソースを検出したと表示したか
- 本文が会話へ渡ったと直接確認できる情報
- 二つのワークスペースで同じ本文が再利用されたか
- 手動で貼り付けた依頼と、自動的に参照された指示の違い
- HOME、User、organization、ワークスペース由来のほかの指示が混ざった可能性
- 保存、検出、本文投入、出力、解除のうち未確認の段階

回答が似ているだけでは、User instruction の検出や本文投入を断定しません。

## 中止条件

- 対象ホスト、利用資格、所有者の承認、保存先のいずれかが不明
- 既存設定と今回の追加分を区別できない
- 今回の追加分だけを解除できない
- 既存の User instructions や Settings Sync を一括でリセットする必要がある
- ワークスペース内のファイルを User 指示の代替として扱う必要がある

中止しても HC-005 本編の分類と草稿は完了できます。

## 本編へ戻る

この試行の観察は、合成カードの設計比較とは別に保ちます。HOME の実際のパスや既存の指示本文は
共有せず、安全な要約だけを残してください。
