# 入れ子の AGENTS.md を別環境で探索する

**言語:** **日本語** / [English](../../../en/challenges/hc-003/optional/nested-discovery.md)

[HC-003 本編へ戻る](../README.md)

## 目的

ルートとサブディレクトリに置いた `AGENTS.md` が、利用中のクライアントでどのように検出・参照されるかを、本編とは別の安全な環境で観察します。

nested AGENTS は Experimental 機能です。対応状況や挙動は、クライアントやバージョンによって変わる可能性があります。パスが表示されたこと、本文が利用されたこと、回答に影響したことを同じものとして扱いません。また、親と子の厳密な継承順や「常に子が優先される」という規則も仮定しません。

参考: [VS Code Custom instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions)

## 前提

- 本編の比較を終えているか、本編とは完全に分けて記録できる
- 破棄または元に戻せる、自分が管理するリポジトリまたはワークツリーを用意できる
- 利用中の VS Code と GitHub Copilot が nested AGENTS に対応しているか確認できる
- `chat.useNestedAgentsMdFiles` が現在のクライアントに存在する場合、その意味と現在値を公式説明または設定画面で確認できる
- ファイルごとに新しい会話を用意できる

## 権限と安全

- Experimental 機能を有効にする必要がある場合は、環境所有者の許可を得ます。
- 既存の `AGENTS.md`、User/organization 設定、Memory は変更も削除もしません。
- 本編のワークツリーや結果を使い回さず、使い捨て環境だけで試します。
- シークレット、非公開データ、実在する利用者や受注をプロンプトに含めません。
- trust やポリシーを迂回せず、許可されていない設定変更は行いません。

## 手順

1. 使い捨てリポジトリのルートと、調査するサブディレクトリを一つ選びます。
2. 現在のクライアントとバージョン、ワークスペースルート、nested 機能の対応状況、設定値を記録します。設定を変更する場合は、許可の有無と元の値も記録します。
3. ルートとサブディレクトリに、内容を区別できる短い `AGENTS.md` を新しく作成します。既存のファイルがある場合は上書きせず、中止します。業務上の答えではなく、出力形式など、影響のない観察用の規則を使います。
4. サブディレクトリ内のファイルと、その外にあるファイルを一つずつ対象にし、同じ短い読み取り依頼を別々の新しい会話で送ります。
5. クライアントが示す参照元、明示的な添付の有無、回答を記録します。明示的に添付した試行は、自動検出の観察と分けます。
6. 作成したファイルと変更した設定を一覧で確認し、自分が追加したものだけを元に戻します。

## 観察すること

- ルートとサブディレクトリの各ファイルを保存した場所
- クライアントが表示した検出または参照元
- 本文が利用されたと確認できる UI 上の情報
- 対象ファイルによって回答が変わったか
- 親子の指示が矛盾した場合ではなく、矛盾しない指示でも過剰適用や対象漏れが起きたか
- 表示がない、または本文利用を確認できない箇所

回答に観察用の言葉が現れただけで、自動検出や本文投入が行われたとは判断しません。

## 停止条件

- クライアントの対応状況、環境所有者の許可、元に戻す方法のいずれかが不明
- 既存のファイルや共有設定を変更しないと試せない
- 本編と同じワークスペースまたは会話を使わないと進められない
- trust や organization ポリシーの回避が必要
- どの指示が使われたか分離できず、追加試行しても安全に観測できない

停止した場合は「未確認」として終え、本編のルートでの比較に結果を加算しません。
