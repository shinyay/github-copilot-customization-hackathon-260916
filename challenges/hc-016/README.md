# HC-016 役立つ記憶だけを残し、古い記憶を捨てよう

**言語:** **日本語** / [English](../../en/challenges/hc-016/README.md)

## シナリオ

受注承認の権限処理を引き継ぐたびに、担当者は同じ二つの `require` を読み直しています。短いメモがあれば便利ですが、古い引用、広すぎるスコープ、別のワークスペースの情報まで残すと、次の担当者を誤らせます。

この演習では実際のMemoryを操作せず、**毎回ソースへ戻る案**と、**根拠付きのメモ候補を選別して保守する案**を設計します。保存候補をゼロにする結論も正解です。

## この機能とは

ここで扱う「記憶」は、後の作業で参照する可能性がある、リポジトリについての短い事実です。常に正しい知識として扱わず、根拠、スコープ、確認した版、再確認条件と一緒に管理します。

| 仕組み | この演習での区別 |
|---|---|
| 会話 | 現在のやり取りの文脈。永続的に保存されたことは示さない |
| Instructions | 人が書いた適用ルール。事実の鮮度管理とは別 |
| VS Code local Memory | User / Repository / Sessionスコープを持つローカルの仕組み |
| GitHub Copilot Memory | cloud agent、code review、CLIなどがリポジトリの事実を扱う仕組み |
| Copilot App の記憶 | 上記とは別の記憶面。この演習からは操作しない |

「`BaseService.require` はnullのactorを拒否する」というメモも、現在のソース、対象のスコープ、再確認条件がなければ安全に再利用できません。「記憶しました」という応答だけでは、保存、持続、別の会話での再参照を確認したことにはなりません。

- [Use memory with agents in VS Code](https://code.visualstudio.com/docs/agents/run/memory)
- [About GitHub Copilot Memory](https://docs.github.com/en/copilot/concepts/agents/copilot-memory)

## 向いていること / 向いていないこと

**向いていること**

- ソースへ戻れる短い事実の候補を、スコープ、引用、鮮度と一緒に設計する
- 保存しない情報と、判断を保留する情報を説明する
- 更新、撤回、再確認の担当と条件を決める
- 古いメモや別のスコープのメモを、現在のソースと照合する

**向いていないこと**

- 個人の好み、実在人物の権限、シークレット、第三者情報を収集する
- メモがあればソースを読まなくてよいと保証する
- Memory の有効・無効による品質差を測定済みと主張する
- 比較のために既存の記憶や User 設定を一括削除する

## ゴール

次を説明できる引き継ぎ案を作ります。

1. ソースから毎回確認する情報と、短いメモの候補にできる情報
2. 残す、残さない、保留するという判断と、そのスコープ
3. 根拠、鮮度、再確認条件、更新・撤回方法
4. 古い候補、広すぎる候補、無関係な候補の扱い
5. 実際のMemoryを使わなくても成立する代替手段

## 準備

1. リポジトリ全体の共通準備は [#始め方](../../README.md#始め方) を参照します。
2. `starter/` の `.template` はそのまま残し、記入用のコピーを任意の作業場所へ作ります。
3. Javaソースを読める場合は、ソースマップにある二つのシンボルを確認します。
4. Javaソースを読めない場合は、固定事実をこの演習の有限入力として使います。実行結果や過去の設計理由は補いません。
5. Memory、User 設定、既存メモは変更しません。

固定事実は次の6行です。

```text
教材用の固定事実。対象はこの演習用repositoryだけであり、個人の好みではない。
BaseService.requireはactorがnullならauthentication.requiredを送出し、それ以外はActor.requireへ委譲する。
Actor.requireはADMINを許可し、そうでなければ指定されたroleのどれかを要求する。
根拠: wholesale-core/src/main/java/jp/co/tsubame/wholesale/service/BaseService.java の require、
wholesale-core/src/main/java/jp/co/tsubame/wholesale/common/Actor.java の require。
これは固定ソースの読解であり、Java/DB実行や実際の利用者の権限を確認した結果ではない。
```

候補カードは次の役割を持ちます。

| カード | 内容 |
|---|---|
| `card-p` | 現在の固定事実とソース参照を持つ候補 |
| `card-q` | null actor を許可すると書いた、意図的に誤った合成候補 |
| `card-r` | 正しい事実にUser全体の広いスコープを付けた合成候補 |
| `card-s` | 別の架空ワークスペースにある無関係な候補。`KEEP-UNCHANGED` を保つ |

## 試してみる

1. **読み取り経路を分ける**
   ソースから読む経路、固定事実を手動で渡す経路、将来Memoryから参照する経路の違いを設計用紙に書きます。三つ目はこの演習では実行しません。
2. **候補を選別する**
   各カードについて、主張、ソースによる裏付け、スコープ、鮮度、残す、残さない、保留するという判断、再確認条件を記録します。
3. **保守方法を決める**
   ソースが変わった、引用が主張を裏付けない、スコープが広がった、という場合の更新、撤回、停止方法を決めます。全消去は代替手段にしません。
4. **引き継ぎ原稿を作る**
   候補となる事実、ソースのパスとシンボル、スコープ、再確認条件、担当、意図的に残さない情報、未確認事項を簡潔にまとめます。
5. **Copilot にレビューを依頼する**
   固定依頼、固定事実、カード、記入した用紙を渡し、実際のMemoryを操作せず、根拠と未確認事項を保ったレビューだけを依頼します。
6. **人がソースへ戻って確認する**
   Copilotの提案を正解として扱わず、card-p / q / rの主張とcard-sが対象外であることを確認します。

## 任意: 比較する

同じ固定入力を使い、別々の新しい会話で次を手動比較できます。

- 案A: 永続メモを作らず、毎回ソースマップから確認する
- 案B: 選別した不活性な引き継ぎ原稿を先に読み、必要な箇所だけソースで再確認する

ソースへ戻りやすいか、誤情報を残すリスク、スコープの狭さ、再確認と保守の負担を比較します。順序による影響や会話の残留を分離できない場合は、優劣を断定しません。

## 確認ポイント

- 会話、Instructions、各 Memory の違いを説明できる
- 事実にソースのパス、シンボル、スコープ、未確認事項が付いている
- 保存ゼロを含む採否に理由がある
- card-qをソースと照合し、card-rのスコープを検討している
- card-s をこの演習の都合で変更・削除していない
- 実際の保存、持続、別の会話での再参照を観測済みと書いていない

## 制約・代替手段・安全

- この演習ではMemoryへの保存、読み出し、更新、削除、全消去を行いません。
- 個人情報、シークレット、実在人物の権限、非公開ログを候補にしません。
- Javaソースを読めない場合も、固定事実とソースマップだけで設計を完了できます。
- 利用中のクライアントがMemoryに対応していなくても、選別、スコープ、鮮度、保守の設計までで完了できます。
- 既存メモを分離できない場合、自分の候補だけを安全に戻せない場合、全消去が必要な場合は、実操作に進みません。
- 整理するのは自分で作った作業用コピーだけです。既存のMemory、User設定、他人のメモ、ソースは削除しません。
