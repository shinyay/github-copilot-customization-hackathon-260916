# VS Code local Memory を試す前の探索ガイド

**言語:** **日本語** / [English](../../../en/challenges/hc-016/optional/local-memory.md)

## 目的

[HC-016 の本編](../README.md)で設計した短い事実の候補を、将来VS Code local Memoryで安全に試せるか確認するための補足ガイドです。この文書を読むだけでは、Memoryへの保存や設定変更は行われません。

VS Code local Memory、GitHub Copilot Memory、Copilot Appの記憶は別の仕組みです。試す対象とスコープを最初に明示します。

## 前提

- 利用中の VS Code と GitHub Copilot が対象機能をサポートしている
- 組織ポリシーとワークスペースの利用条件を確認できる
- User / Repository / Sessionなど、実際に選べるスコープを確認できる
- 開始前の状態と、自分が追加した候補だけを識別できる
- 対象クライアントの公式手順を参照できる

## 権限と安全

- 専用スコープへの保存、読み出し、限定的な更新、削除を行う場合は、それぞれ事前に許可を得ます。
- シークレット、個人の好み、実在人物の権限、第三者情報、非公開ログは保存しません。
- 既存メモの全消去、他人のメモの変更、User 設定の初期化は行いません。
- このリポジトリの `.template` を有効なMemory設定として自動配置しません。

## 手順

1. 対象が **VS Code local Memory** であることと、利用可能なスコープを公式UIまたは文書で確認します。
2. 開始前に、対象のスコープ、既存の状態を確認できる範囲、復元方法を記録します。
3. 本編のcard-pを参考に、個人情報を含まない短い教材用の事実を一つだけ用意します。
4. 許可がある場合に限り、対象クライアントが公開している手順で、その一件を保存します。未確認のAPI名やコマンドは作りません。
5. 同じ会話での読み出しと、対応している場合に限って行う別の会話での再参照を分けて確認します。
6. ソースが変わったと想定し、同じ一件だけを更新または撤回する方法を確認します。
7. 自分が追加した一件だけを元に戻し、開始前状態と比較します。

## 観察すること

- クライアントと機能名
- 選んだスコープと、その根拠
- 開始前に見えた状態
- 保存、読み出し、別の会話での再参照、更新、削除のうち、実際に行った操作
- ソースのパス、シンボル、確認した版、再確認条件
- 復元結果と、確認できなかったこと

原稿を作ったこと、保存を依頼したこと、実際に保存・再参照できたことは別々に記録します。

## 停止条件

- 既存メモと今回の一件を分離できない
- 自分が追加した一件だけを安全に戻せない
- 全消去、他人のメモ変更、User 設定削除が必要になる
- 対象のスコープや製品面を確認できない
- 未確認のAPIや別の記憶サービスを迂回しなければ進めない

該当する場合は実操作をやめ、本編の不活性な設計だけを完成させます。
