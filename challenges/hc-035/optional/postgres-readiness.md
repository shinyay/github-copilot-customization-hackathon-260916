# PostgreSQL の準備状況を確認する

**言語:** **日本語** / [English](../../../en/challenges/hc-035/optional/postgres-readiness.md)

[← HC-035 のメインシナリオ](../README.md)

## 目的

DB テストを始める前に、専用の PostgreSQL、接続範囲、オプトイン、クリーンアップの条件がそろっているかを確認します。このガイド自体は DB を準備せず、接続やテストも実行しません。

## 前提

- JDK 8 と Maven 3.9 系を確認できる
- DB テストのオプトイン条件を確認できる
- 承認済みの専用 PostgreSQL インスタンス/データベースがある
- DB 所有者、ネットワーク/ランナーのポリシー、復元範囲を特定できる

## 権限と安全

- DB の利用、接続、フィクスチャ、限定テスト、停止、クリーンアップについて、DB 所有者の承認を得ます。
- 共有 DB/本番 DB、本番データ、未承認のフィクスチャは使いません。
- 認証情報を教材へ保存、表示、転載しません。

## 手順

1. エンジン/バージョン、専用 DB 名、所有者、ネットワーク経路を記録します。
2. オプトインが有効な場合だけ、実行対象のテストを特定します。
3. フィクスチャとクリーンアップの対象を、自分が追加するデータだけに限定します。
4. JDK/Maven の適合と DB 接続可否を別々に確認します。
5. 承認後にテストを行う場合は、コマンド、終了結果、クリーンアップの結果を別々に記録します。

## 観測すること

- 専用 DB と共有 DB/本番 DB の分離
- オプトインの有無
- 接続成功とテスト成功の違い
- スキップと成功の違い
- クリーンアップが自分の追加分だけに限定されているか

## 停止条件

- JDK/Maven、DB 所有者、専用 DB、ネットワーク、復元範囲のいずれかが不明
- 共有 DB/本番 DB または本番データが必要
- オプトインなしのスキップをテスト成功と扱う必要がある
- クリーンアップの対象を限定できない
