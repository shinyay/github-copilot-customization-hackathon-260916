# Cloud Agent setup を観測する

**言語:** **日本語** / [English](../../../en/challenges/hc-035/optional/cloud-setup.md)

[← HC-035 のメインシナリオ](../README.md)

## 目的

承認済みの専用リポジトリと Ubuntu ランナーで、Cloud Agent setup の保存、採用、各ステップ、失敗後の Agent の開始を、範囲を限定して観測します。

## 前提

- Cloud Agent、GitHub Actions、対象リポジトリ、ランナーを利用できる
- default ブランチと setup ファイルのリビジョンを特定できる
- JDK 8、Maven 3.9 系、ネットワーク要件を確認できる
- ランナー/Actions/モデルの費用上限を決められる

## 権限と安全

- active workflow の保存、検査トリガー、ランナーの利用、Cloud Agent のタスク、終了時の解除について事前承認を得ます。
- シークレットの値を読み、表示、移動、要求しません。
- ファイアウォール、TLS、プロキシ、共有ランナーの設定を緩和しません。

## 手順

1. setup ファイルのリビジョン、job、steps、permissions、ランナー、timeout を記録します。
2. ワークフローの構文とバージョン確認の設計を確認します。
3. 承認された最小の検査で、setup の採用と各ステップを観測します。
4. 必須ステップが失敗した場合は、残りのスキップ、残っている状態、Agent の開始を分けて記録します。
5. テストを実行した場合だけ、コマンドと結果を記録します。
6. 実験後は自分が追加した workflow だけを解除します。

## 観測すること

- default ブランチ上の setup のリビジョン
- JDK/Maven の実際のバージョンと範囲への適合
- 依存関係の準備とテストの違い
- 失敗したステップ、スキップ、Agent の開始
- ワークフローの検査と Cloud Agent での採用の違い

## 停止条件

- 利用資格、承認、Ubuntu ランナー、default ブランチ/ref、setup のバイト列のいずれかが不明
- Actions/ランナー/モデルの費用上限がない
- シークレットやネットワークポリシーの緩和が必要
- setup の失敗後に Agent が開始したことを、成功と扱う必要がある
