# Plugin を有効化する前の確認ガイド

**言語:** **日本語** / [English](../../../en/challenges/hc-014/optional/plugin-enable.md)

[HC-014 本編へ戻る](../README.md)

## 目的

HC-014で作成した不活性なAgent Pluginの原稿を、将来、承認済みの実験環境で試す前に確認する項目を整理します。
このページは、インストール、登録、有効化の手順ではありません。本編の `.template` を有効なファイルに変更しません。

観察したいことは、次のように分けます。

1. クライアントがAgent Plugins 1.0をサポートしているか。
2. パッケージ全体をレビューできたか。
3. 設定上の登録・有効状態がどう保存されるか。
4. Plugin が発見されたか。
5. 必要な場面で `order-import-evidence` の本文が読み込まれたか。
6. 更新・無効化後に、古いコピーや同名 Skill が残っていないか。

設定値、UI表示、検出、本文の読み込みは、それぞれ別の観察項目です。

## 前提

- HC-014本編のv1 / v2原稿、版台帳、完全復元の確認が完了していること。
- Agent Plugins 1.0に対応するクライアントと、その時点の公式文書を確認できること。
- 本編とは別の専用ワークスペースと新しい会話を使えること。
- Copilotと対象リポジトリの利用資格、組織のPluginポリシーを確認できること。
- パッケージに含まれるすべてのコンポーネントをレビューできること。

実施時点の仕様は次で確認してください。

- [VS Code Agent plugins](https://code.visualstudio.com/docs/agent-customization/agent-plugins)
- [Agent Plugins manifest](https://agent-plugins.org/plugin-authors/manifest)

ほかのクライアントや古いUIの説明を、現在の環境で利用できるかどうかの判断に使わないでください。

## 権限と安全

- インストール、登録、有効化、設定変更には、環境所有者による別途の承認が必要です。
- 本編の `starter\` や `work\` にある `.template` は変更せず、実験は承認された使い捨て環境で行います。
- パッケージ名だけで信頼せず、Skill以外のコンポーネントが含まれていないか、ディレクトリツリー全体を確認します。
- marketplaceからの追加ダウンロード、公開、Profileの変更、ホームディレクトリの削除を、確認作業の副作用として発生させません。
- 既存 Plugin、手動 Skill、ユーザー設定、組織設定を削除して条件を作りません。
- Hook、MCP、Agent、rules、promptsが追加されていたら、本シナリオのパッケージとしては停止します。

## 手順

1. `work\package\v1` と `work\package\v2` の全ファイルを一覧にし、マニフェストと一つのSkillだけで構成されているか確認する。
2. ヘルパーの結果と生のハッシュを再確認し、同じ版の手動Skillとパッケージ内のSkillが一致するか確認する。
3. クライアントの公式文書で、ローカルPluginの場所、設定のスコープ、有効状態の保存方法を確認する。
4. `chat.plugins.enabled`、`chat.pluginLocations` など、利用中のクライアントが実際に案内する設定名と意味を確認する。
5. ワークスペース設定として再現するのか、Profileまたはユーザースコープに置くのかを決め、追跡可能性と実行権限を分けて考える。
6. 別途承認を得た場合に限り、使い捨て環境で対象のパッケージを一つ登録する。
7. パッケージの検出、Skill候補、本文の読み込み、バージョン表示をそれぞれ観察する。
8. v2への更新後、古いv1や同名のSkillがほかの出所に残っていないか確認する。
9. 無効化または実験の終了後も、設定、候補、本文、会話のコンテキストが残っていないか、それぞれ確認する。

本リポジトリでは手順 6 以降を実行しません。実験環境で行う場合も、公式文書と承認範囲を優先してください。

## 観察すること

- クライアント、版、Pluginへの対応状況
- パッケージの正確なパスと生のハッシュ
- 設定を保存したスコープと出所
- Pluginの検出、Skillの候補表示、本文の読み込み
- パッケージのバージョンとSkillのマーカーの対応
- 同名の候補、旧版、手動コピー、ホームディレクトリにある別の出所
- 無効化後に残る設定、候補、会話のコンテキスト

`starter\fixtures\lifecycle-origins.json.template` の `enabled` は合成値です。
実際のクライアントでの有効状態、候補の消失、本文の読み込み停止を証明するものではありません。

## 停止条件

- 対応するクライアント、利用資格、組織ポリシー、環境所有者の承認を確認できない。
- パッケージ全体をレビューできない、または想定外のコンポーネントがある。
- 本編の `.template` を外す、実際の探索先へ移す、既存設定を変更する必要がある。
- 既存 Plugin や他人の設定を削除しなければ同名候補を分離できない。
- パッケージ内のSkillと手動Skillの生のバイト列、またはv1/v2の一要因差分が一致しない。
- 設定値、検出、本文の読み込みのどれを観察したか区別できない。

停止した場合も、HC-014 本編の版・構成・復元の学習は完了できます。

## 終了時の扱い

実験で得られる結果は、特定のクライアント、版、設定のスコープ、時点に限られます。
構造を検査するヘルパーの成功だけを根拠に、インストール、検出、読み込み、更新、無効化に成功したと判断しないでください。
片付けは、自分が承認を得て追加したものだけに限定し、既存のPlugin、ホームディレクトリ、他人の設定には触れません。
