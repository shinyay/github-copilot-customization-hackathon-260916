# terminal sandboxを評価する探索ガイド

**言語:** **日本語** / [English](../../../en/challenges/hc-018/optional/terminal-sandbox.md)

## 目的

[HC-018 の本編](../README.md)とは別に、Previewのterminal sandboxを限定的に評価するための条件を整理する補足ガイドです。本編の合成パケットや `node --version` の正常出力を、実際のsandboxの観察結果として扱いません。

## 前提

- 対応するクライアントとPreview機能を公式資料で確認できる
- 実行ホストがmacOS、Linux、または対応が明記されたWSL2である
- 分離したワークスペースと、自分が所有するダミーのパスを用意できる
- 開始前状態と復元方法を確認できる
- 追加の依存導入なしで、限定操作を行える

Windowsネイティブ環境しか使えない場合は、対応状況を推測せず、文書での確認までに留めます。

## 権限と安全

- sandboxの有効化、通常の承認、ダミーのパスへの限定操作、復元について、事前に許可を得ます。
- 権限昇格、保護の解除、ホームディレクトリ、ネットワーク、既存の承認規則のリセットは対象にしません。
- このリポジトリに有効な設定やプローブ用プログラムを追加しません。
- 自分が所有するダミーのパス以外には書き込みません。

## 手順

1. クライアントの公式資料で、対応するOS、対象のツール、制限事項、設定場所を確認します。
2. 分離したワークスペースと、自分が所有するダミーのパスを決め、開始前の状態を記録します。
3. 操作内容、cwd、変更範囲、期待するOSの結果とプログラムの結果を事前にレビューします。
4. 必要な許可がすべて得られた場合に限り、公式UIでsandboxを有効にし、通常の承認を経て限定操作を一度行います。
5. `proposal`、`approval`、`execution`、OSの結果、プログラムの結果を、それぞれ記録します。
6. 自分の変更と設定だけを元へ戻し、開始前状態と比較します。

## 観察すること

- クライアント、ホストOS、対象のterminalツール
- sandbox設定を確認できる範囲
- `proposal` と人の判断
- `execution` が始まったか
- OSとプログラムがそれぞれ返した結果
- ダミーのパスの変更と復元
- 確認できなかった境界

正常に実行できたことは、拒否境界の証明にはなりません。また、一つの拒否は、すべてのファイルシステム、ツール、ネットワークが保護されていることの証明にはなりません。

## 停止条件

- Windowsネイティブ環境、未対応のOS、未確認のPreviewしか使えない
- 依存関係の導入、権限昇格、保護の解除、ホームディレクトリやネットワークへの操作が必要
- 自分が所有するダミーのパスと復元方法を確認できない
- User / Profile 設定への追跡不能な変更が必要
- 承認を迂回またはリセットしなければ観察できない
