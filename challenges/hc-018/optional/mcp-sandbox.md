# stdio MCP sandboxを評価する探索ガイド

**言語:** **日本語** / [English](../../../en/challenges/hc-018/optional/mcp-sandbox.md)

## 目的

[HC-018 の本編](../README.md)や [terminal sandbox のガイド](terminal-sandbox.md)とは別に、ローカルのstdio MCPサーバーのsandbox境界を限定的に評価するための条件を整理する補足ガイドです。terminalの結果をMCPの結果として扱いません。

## 前提

- macOSまたはLinuxのローカルstdio経路を利用できる
- すでにレビュー済みの限定されたサーバーとダミー操作がある
- サーバーの起動方法、トランスポート、信頼設定、sandbox設定、承認の動作を確認できる
- 分離したワークスペース、開始前の状態、復元方法を用意できる
- 対応するクライアント、Copilot、MCP機能を利用できる

リモートサーバー、別のトランスポート、Windowsへの対応は推測しません。

## 権限と安全

- ローカルstdioサーバーの信頼設定と起動、sandbox設定、承認の動作、ダミー操作、復元について、事前に許可を得ます。
- 新しいサーバー、依存関係、認証情報、リモートトランスポート、ホームディレクトリやネットワークへのプローブは追加しません。
- サーバーのソースと起動方法をレビューできない場合は実行しません。
- このリポジトリに有効なMCP設定やプローブ用プログラムを追加しません。

## 手順

1. サーバーのソース、起動コマンド、トランスポート、利用するツールをレビューします。
2. sandboxと承認がどの段階に作用するかを、境界マップに整理します。
3. 開始前のサーバー、ワークスペース、ダミーの対象の状態を記録します。
4. 必要な許可がすべて得られた場合に限り、ローカルstdioサーバーを起動し、限定されたダミー操作を一度提案します。
5. ツールの選択、`proposal`、`approval`、`execution`、OSの結果、プログラムの結果を、それぞれ記録します。
6. サーバーを停止し、自分が変更した設定とダミーの対象だけを元に戻します。

## 観察すること

- クライアント、ホストOS、サーバー、トランスポート、ツール
- サーバーの信頼設定と起動方法
- sandboxと承認を確認できる範囲
- `proposal` と人の判断
- OSとプログラムの結果
- サーバーの停止とワークスペースの復元
- 観察できなかった境界

一つのstdioサーバーの観察結果を、terminal、リモートMCP、すべてのツール、すべてのOSに当てはめません。

## 停止条件

- Windows、リモートトランスポート、未レビューのサーバーしか使えない
- 承認の動作が許可条件と一致しない
- 認証情報、ネットワーク、ホームディレクトリ、依存関係の導入、追加のプローブ先が必要
- サーバーのソースや復元方法を確認できない
- User設定や別のサーバーを迂回しなければ進めない
