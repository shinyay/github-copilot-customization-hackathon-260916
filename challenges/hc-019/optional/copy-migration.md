# 自己所有のコピー移行を観察する

**言語:** **日本語** / [English](../../../en/challenges/hc-019/optional/copy-migration.md)

## 目的

対応製品で、自己所有の無害なコピーを移行します。ソースと移行先、メタデータ、原本が保たれることを個別に確認し、コピーが成功しただけで適用や自動同期まで成功したとは判断しません。

## 前提

- 移行に対応する製品バージョンと対象ホスト
- 自分が所有する使い捨て可能なコピー
- ソース、移行先、同名項目との競合、メタデータ、保存場所の設定を確認できること
- 原本を保持したまま戻せること

## 権限・安全

- 移行先の作成や設定変更の対象を限定し、事前に承認を得ます。
- `deleteOriginal` の使用、同名項目の上書き、通常のプロファイル / ホームの変更は行いません。
- このリポジトリの `starter/**/*.template` は移行対象にしません。
- 非公開の内容や他人のコピーは使いません。

## 手順

1. 現在の製品ドキュメントで、対象形式、ソース、移行先、引き継がれるメタデータを確認します。
2. 自己所有のコピーについて、本文、メタデータ、保存場所、開始前の状態を記録します。
3. 原本を保持する設定で、許可された移行操作を一度行います。
4. 移行先の本文とメタデータをソースと比較します。
5. 一覧表示（listed）、有効化（enabled）、検出（discovery）、適用（application）は別々に観察し、本文が一致したことから推測して補いません。
6. rollbackが必要な場合も原本は残し、自分が作成した移行先だけを整理します。

## 観察すること

- 本文とメタデータのどちらが引き継がれたか
- ソースと移行先が自動同期するかどうかを、未確認のまま扱っているか
- 保存場所の設定や同名項目との競合がどう扱われたか
- 移行後の検出（discovery）や適用（application）を示す直接の情報があるか

## 停止条件

- 原本の削除、同名項目の上書き、通常のプロファイル / ホームの変更が必須になる
- ソース、移行先、メタデータ、rollbackを確認できない
- 自己所有のコピーを分離できない
- 製品ドキュメントと実画面が一致しない
