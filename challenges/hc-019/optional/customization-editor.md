# Customizations editorで自己所有のコピーを観察する

**言語:** **日本語** / [English](../../../en/challenges/hc-019/optional/customization-editor.md)

## 目的

管理UIに表示される候補、スコープ、有効状態と、実際のリクエストへの適用を分けて観察します。[メインシナリオ](../README.md)の合成インベントリを、実際のUIで得た結果として扱わないための補足です。

## 前提

- Customizations editorに対応するVS Code / GitHub Copilot環境
- 組織ポリシーで利用が認められたワークスペースとハーネス
- 自分が所有する無害な既存カスタマイズ
- クライアントのバージョン、チャネル、対象ハーネスを記録できること

## 権限・安全

- このリポジトリの `starter/**/*.template` は有効化しません。
- 通常のプロファイル、他人のカスタマイズ、User / home、原本は変更しません。
- 画面やログを保存する場合は、秘密、個人情報、非公開コードを除きます。
- 有効化やテスト用リクエストが必要な場合は、対象と後片付けの範囲を限定し、事前に承認を得ます。

## 手順

1. クライアント、チャネル、ワークスペース、選択したハーネス、開始前の状態を記録します。
2. 現在の製品ドキュメントに従ってCustomizations editorを開きます。
3. 自己所有の安全な項目について、表示名、スコープ、ソース、`listed`、`enabled` を記録します。
4. 許可されている場合はハーネスを切り替え、候補表示が変わるかを確認します。
5. 適用の確認まで承認されている場合に限り、無害な固定リクエストを一度実行し、UIが示す参照元などの直接情報を記録します。
6. 自分が加えた一時変更だけを戻し、元の状態と比較します。

## 観察すること

- listedとenabledは別の状態か
- harnessごとに候補が変わるか
- 適用を示す直接の情報があるか、それとも出力から推測しているだけか
- 出力が指示に従っていても、有用性を別に評価できているか

## 停止条件

- 対応するUIがない、対象ハーネスが不明、または自己所有の項目を分離できない
- 有効化が必要だが、その承認を得ていない
- プロファイル、User / home、原本、他人の項目を変更する必要がある
- 適用を出力だけから推測するしかない
