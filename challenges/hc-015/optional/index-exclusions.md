# インデックス・検索除外・開いたファイルを分けるガイド

**言語:** **日本語** / [English](../../../en/challenges/hc-015/optional/index-exclusions.md)

[HC-015 本編へ戻る](../README.md)

## 目的

同じ `allocate` と固定ソースについて、text search、semantic search、明示的な添付、
開いているファイルや選択範囲の違いを整理します。
検索除外をACLとして扱わず、インデックスが未準備または未確認の状態を「検索結果0件」に置き換えないことが目的です。

このガイドでは、設定の変更やインデックスの構築は行いません。
[Java 言語サービスのガイド](language-tools.md)とも別の探索です。

## 前提

- HC-015本編とは別のワークスペースと新しい会話を使えること。
- 同じクエリ、固定ソース、除外状態、開いたファイル、選択範囲を記録できること。
- 利用中のクライアントで、インデックスの出所と状態を確認できること。
- Copilot、インデックスサービス、ソースの利用資格と組織ポリシーを確認できること。
- 既存設定の出所を、変更せず読めること。

インデックスの出所は、GitHub、Azure DevOps、その他のワークスペースなどによって異なる場合があります。
状態表示を読めても、構築、通信、検索の成功を確認したことにはなりません。

## 権限と安全

- インデックスの構築、通信、ワークスペース設定の変更には、別途承認が必要です。このガイドでは実行しません。
- ソース、既存の除外設定、組織のcontent exclusionは変更しません。
- `force-add`、User/Profile 設定への切替で再現性の問題を回避しません。
- content exclusion で制限された内容を、明示添付や開いたファイルから迂回して取得しません。
- 検索除外は秘密保護の ACL ではありません。

## 手順

1. クライアント、ランタイムワークスペース、クエリ `allocate`、upstreamテンプレートのリビジョンを記録する。ローカルの `HEAD` との一致は要求しない。
2. `search.exclude`、`files.exclude`、`.gitignore` の実効値と出所を、変更せず確認する。
3. 開いているファイル、タブ、選択範囲を記録する。
4. text/file searchを実行する場合は、対象範囲、除外、返されたパスを記録する。
5. semantic searchを実行する前に、インデックスの出所、状態、利用資格、組織ポリシーを確認する。
6. インデックスを利用でき、別途承認を得ている場合に限り、同じクエリとソースの範囲でsemantic searchを観察する。
7. 明示的な添付を使う場合は、検索結果とは別に、正確なパスと添付表示を記録する。
8. text search、semantic search、明示的な添付、開いているファイルから得たコンテキストを、それぞれ比較する。

### 設定ごとの対象

| 設定 / 状態 | 区別して考えること |
|---|---|
| `search.exclude` | text/grep検索からの除外。Explorerの表示や、すべてのコンテキスト経路を閉じるACLではない |
| `files.exclude` | Explorerと検索への影響。利用中のクライアントの文書と実効値を確認する |
| `.gitignore` | Gitの追跡と検索への影響。開いているファイルや選択範囲のコンテキストとは別に確認する |
| 開いている除外対象ファイル / 選択範囲 | 検索側の除外とは別の経路でコンテキストに入る可能性がある。content exclusionを回避する許可ではない |
| semantic index | 意味検索の準備。ソースの閲覧権や全文の投入を保証しない |

## 観察すること

- クエリ、upstreamテンプレートのリビジョン、ランタイムワークスペースの対象範囲
- 各除外設定の値と出所
- タブ、開いているファイル、選択範囲
- text/file searchで返されたパス
- インデックスの出所、状態、利用資格、組織ポリシー
- semantic searchの要求範囲と返却範囲
- 明示的な添付の正確なパスと表示
- 確認できなかった範囲

Node.jsによる文字列の走査や教材JSONの値は、VS Codeの検索、インデックス、添付を実行した結果ではありません。

## 停止条件

- インデックスの出所、状態、利用資格、組織ポリシーを確認できない。
- 設定の変更、インデックスの構築、既存の除外設定の変更が必要。
- `force-add` や User/Profile 設定への切替が必要。
- 組織の content exclusion を回避する可能性がある。
- クエリ、ソース、除外状態、タブ、選択範囲を方法間で揃えられない。

未確認のsemantic searchの結果は `null` 相当として扱い、空配列や0件に置き換えないでください。
text searchの結果が0件でも、ソースが存在しないこと、読み取りが拒否されたこと、結論が正しいことを意味しません。

## 終了時の扱い

このガイドは、設定とコンテキスト経路の違いを観察するための補足です。
実際のソースのACL、すべてのコンテキストの投入、回答品質、教育効果を証明するものではありません。
