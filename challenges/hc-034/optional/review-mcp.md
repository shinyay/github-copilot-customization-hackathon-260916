# Code review で MCP 接続を観測する

**言語:** **日本語** / [English](../../../en/challenges/hc-034/optional/review-mcp.md)

[← HC-034 のメインシナリオ](../README.md)

## 目的

Copilot code review で、研修専用 MCP ツールの採用と読み取り専用の検索を、範囲を限定して観測します。

## 前提

- Copilot code review と対象リポジトリを利用できる
- 対象 PR/head と要求者を特定できる
- 共有 MCP 設定の所有者と利用者範囲を確認できる
- `training-v1` の生のバイト列と想定されるハッシュを保存できる

## 権限と安全

- 共有設定への最小限の追加、レビューの要求、ツールの呼び出し、終了時の解除について事前承認を得ます。
- `readOnlyHint` を認可、ACL、無害性の保証として扱いません。
- 既定のサーバー、共有利用者、非公開ログを保護します。

## 手順

1. 対象 head、設定のリビジョン、メモのリビジョン/ハッシュを記録します。
2. 共有設定には、研修用サーバーだけを追加します。
3. 承認を得たうえで、レビューを 1 回要求します。
4. ツールの採用、呼び出し、返却を直接確認できる記録だけ残します。
5. 返却内容のコードに基づくセクションを、ソースと照合します。
6. 実験後は自分が追加した設定だけを解除します。

## 観測すること

- レビュー対象の head と設定のリビジョン
- ツールの採用、call ID、引数、返却内容
- 返却されたリビジョン/本文のハッシュ
- `NOT_FOUND`、取得エラー、リビジョンの不一致
- read-only annotation と実装の安全性の違い

## 停止条件

- Copilot code review の利用資格、対象 head、要求者、設定所有者、メモのバイト列のいずれかが不明
- 共有利用者への影響またはレビューの要求について承認がない
- `readOnlyHint` を安全性の保証にしないと続行できない
- `NOT_FOUND` と取得エラーを区別できない
- レビューの要求を無制限に繰り返す必要がある
