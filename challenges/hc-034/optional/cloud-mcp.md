# Cloud Agent で MCP 接続を観測する

**言語:** **日本語** / [English](../../../en/challenges/hc-034/optional/cloud-mcp.md)

[← HC-034 のメインシナリオ](../README.md)

## 目的

研修専用の読み取り専用 MCP サーバーだけを使い、Cloud Agent で設定の保存、サーバーの起動、ツール一覧、採用、呼び出し、返却を、範囲を限定して観測します。

## 前提

- Cloud Agent と対象リポジトリを利用できる
- リポジトリの共有 MCP 設定の所有者を特定できる
- `training-v1` の生のバイト列と想定されるハッシュを保存できる
- シークレットが不要な研修用サーバーと安全な配置先を用意できる

## 権限と安全

- 共有設定への最小限の追加、サーバーの起動、Cloud Agent のタスク、ツールの呼び出し、費用、終了時の解除について事前承認を得ます。
- 既定の MCP サーバーは削除せず、許可リストは `lookup_training_note` だけにします。
- 本番データ、顧客情報、シークレット、実際のエンドポイントは扱いません。

## 手順

1. 既存共有設定を記録し、追加部分と復元方法を決めます。
2. `training-v1` のリビジョンと本文の生のハッシュを保存します。
3. 承認済みの研修用サーバーを起動し、プロトコルとツールのスキーマを確認します。
4. Cloud Agent で対象のサーバー/ツールが採用されたことを直接確認します。
5. `lookup_training_note` を 1 回呼び出し、引数、返却されたリビジョン、本文のハッシュを記録します。
6. コードに基づくセクションをソースと照合します。
7. 自分が追加した設定とサーバーだけを停止・解除します。

## 観測すること

- config saved / syntax / started / listed / adopted / called / returned / supported
- 想定したリビジョンと返却されたリビジョンの一致
- `NOT_FOUND`、引数不正、transport error の区別
- ローカルでのプロトコル成功と Cloud での採用の違い

## 停止条件

- 利用資格、承認、設定所有者、研修用メモのバイト列のいずれかが不明
- 既定設定を保護できない
- シークレットが不要な研修環境に限定できない
- 返却されたリビジョンまたは本文のハッシュが一致しない
- ローカルでのプロトコルの結果だけで、Cloud での採用を主張する必要がある
