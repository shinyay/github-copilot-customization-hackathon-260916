# CLI / App / Cloudを別のクライアントとして調べる

**言語:** **日本語** / [English](../../../en/challenges/hc-025/optional/other-clients.md)

[メインシナリオへ戻る](../README.md)

## 目的

CLI、Copilot App、Cloud Agentなどを別々のクライアントとして調べ、同名のカスタマイズがどこから検出され、どの本文、ツール、承認で使われるかを整理します。Agent HostとCloud Agentを同義語として扱いません。

## 前提

- 調べるクライアント、バージョン、チャネル、実行場所を1つに特定できる
- そのクライアント、モデル、Pluginコンポーネント、Cloud実行の利用資格を確認できる
- 通常環境と分離した検証先と、終了後の復元方法がある

## 権限・安全

- インストール、ログイン、同期、Cloud操作、モデルの利用、外部送信、費用を個別に承認します。
- 資格情報、トークン、通常のプロファイル、同期設定、既存ブランチを無断で変更しません。
- 標準のPluginコンポーネントと、クライアント固有の名前空間を分けて確認します。
- クライアントで不明な値を、別のクライアントの結果や現在のバージョンから補いません。

## 手順

1. 対象クライアントを1つ選び、公式文書とバージョンを記録します。
2. `../starter/customizations/` から確認する形式を1つ選びます。
3. そのクライアントについて文書化されている配置方法、インストール方法、必要な権限を確認します。
4. 承認済みの隔離環境で、固定依頼と固定パケットを使って1回だけ確認します。
5. discovery、loading、effective tools、approval、外部通信、費用、エラーを記録します。
6. 自分が追加した構成だけを元に戻してから、別のクライアントを新しい記録として扱います。

## 観察すること

- クライアント / バージョン / 実行場所
- カスタマイズの種類 / ソース / discovery
- body loading
- 宣言されたツール / 実効ツール
- approval / ネットワーク / 費用
- 結果 / 制限 / 後片付け

## 停止条件

- クライアント、バージョン、公式の対応範囲を確認できない
- インストール、ログイン、同期、Cloud操作、外部送信、費用の承認がない
- 非公開コードや資格情報を送信対象から除外できない
- 別のクライアントの結果を流用しなければ結論を出せない
- 変更を安全に戻せない

停止理由を記録し、[メインシナリオ](../README.md)の可搬性診断へ戻ります。
